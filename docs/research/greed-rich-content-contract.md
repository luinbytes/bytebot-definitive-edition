# Greed rich-content compatibility contract

Frozen 2026-08-24 before implementation. This contract combines Greed's current public documentation with its pinned complete English registry at [`3dadc418`](https://github.com/greedbest/i18n/tree/3dadc41852a09567add8a6b2b522d5e2b1a53b2f). The live command catalog is client-rendered and currently presents a Cloudflare verification page to direct inspection, so no undocumented runtime behavior is inferred from it.

| Surface | ByteBot contract |
| --- | --- |
| Embed scripts | `/embed create`, `copy`, `save`, `list`, `raw`, `rename`, `remove`, `publish`, `published`, and `unpublish`; `/variables` lists supported substitutions. Legacy aliases `/createembed` and `/copyembed` remain discoverable. Scripts support content, up to 10 embeds, authors, fields, footers, images, thumbnails, timestamps, and link/custom buttons with Discord's documented per-field and 6,000-character aggregate limits. Saved embeds follow their owner across servers. Publishing is capped at the highest public allowance of 10 per owner and is exposed through in-bot discovery because ByteBot has no external Greed discover site. Sources: [embeds](https://greed.best/docs/resources/scripting/embeds), [publishing](https://greed.best/docs/resources/scripting/publishing), [Discord message limits](https://docs.discord.com/developers/resources/message). |
| Components V2 | `{cv2}` layouts support text, sections, link/custom buttons, action rows, disabled display selects, separators, galleries, thumbnails, and containers. They cannot mix legacy content/embeds, use the irreversible Components V2 flag, reject invalid URLs, and enforce Discord's 40-component ceiling plus Greed's documented nesting and row limits. Source: [Greed components](https://greed.best/docs/resources/scripting/components), [Discord component reference](https://docs.discord.com/developers/components/reference). |
| Custom scripts | `/custom add`, `list`, `test`, `raw`, `rename`, `remove`, and confirmed `reset`; names normalize to 1–32 lowercase letters, digits, `_`, or `-`, maximum 100 per server. Manage Server is required to mutate or inspect them. A custom button renders the named script ephemerally for its clicker, increments use count, and fails closed after removal or rename. Source: [custom scripts](https://greed.best/docs/configuration/custom-scripts). |
| Tags | `/tag add`, `edit`, `remove`, `rename`, `reset`, `send`, `list`, `search`, `random`, and `author`; `/tag settings` maps the pinned `settings tags on|off` switch into ByteBot's slash grammar. Tags are globally named, retain an author, render scripts in DMs or servers, and only their author or a Manage Server member may mutate them. Literal mentions never ping. Source: [pinned tag registry](https://github.com/greedbest/i18n/tree/3dadc41852a09567add8a6b2b522d5e2b1a53b2f/locales/en/commands/utility/tag) and [pinned tag setting](https://github.com/greedbest/i18n/blob/3dadc41852a09567add8a6b2b522d5e2b1a53b2f/locales/en/commands/settings/tags.json). |
| Pagination | `/pagination set`, `add`, `update`, `remove`, `delete`, `reset`, `list`, and `restorereactions`; only ByteBot-authored messages containing an embed can be registered, with at most 10 pages. Current docs define `remove` as removing one page, superseding the pinned registry's older delete alias. Navigation uses durable left/right reactions and survives restart. Source: [pagination](https://greed.best/docs/resources/scripting/pagination) and [pinned registry](https://github.com/greedbest/i18n/tree/3dadc41852a09567add8a6b2b522d5e2b1a53b2f/locales/en/commands/server/pagination). |
| Managed webhooks | `/webhook create`, `send`, `edit`, `delete`, `list`, plus pinned `/webhook avatar`. Manage Webhooks is required. Short IDs expose no Discord credential. ByteBot persists webhook/message IDs only, reacquires bot-authorized webhook objects when needed, suppresses mentions, validates scripts, and never places tokens or webhook URLs in storage, logs, or public responses. Sources: [Greed webhooks](https://docs.greed.best/server-configuration/webhooks), [pinned registry](https://github.com/greedbest/i18n/tree/3dadc41852a09567add8a6b2b522d5e2b1a53b2f/locales/en/commands/utility/webhook), [Discord webhook resource](https://docs.discord.com/developers/resources/webhook). |
| Embed colors | `/embed colors`, `setcolor`, and `resetcolors` map Greed's paywalled server embed-color setting into the existing Utility/Admin split. Manage Server is required; ByteBot exposes the highest public behavior without an entitlement gate. Source: [pinned embed setting](https://github.com/greedbest/i18n/blob/3dadc41852a09567add8a6b2b522d5e2b1a53b2f/locales/en/commands/settings/embed.json). |

All rich-content sends default to `allowedMentions: { parse: [] }`. User-supplied URLs accept only absolute HTTP(S), plus documented `attachment://` references where Discord supports them. Destructive reset operations require explicit confirmation. The implementation reuses `automation_rules`, the existing lifecycle embed parser where it is already correct, and discord.js 14.27's installed Components V2 builders; no dependency or new persistence framework is introduced.

The public test seams are: slash command registration/execution, script-to-message payload rendering, persisted ownership operations through the existing automation module, and reaction/component/webhook Discord adapters. Tests observe those interfaces and their safety outcomes rather than private helpers.
